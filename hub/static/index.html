A coding agent you can drive from your terminal, browser or phone.

tamale is an open-source coding agent written in Rust. Start a session in your terminal, then pick it up from any browser or your phone through this hub, end-to-end encrypted.

Install GitHub Get a key
  • A full agent harnessTools, permission prompts, undo, sessions and compaction are built in.
  • Bring your own modelAn Anthropic API key, any OpenAI-compatible provider (DeepSeek, Kimi, Gemini, OpenRouter, …), or your existing Claude Code or Codex sign-in.
  • Terminal, web and iOSOne session, wherever you are. Longer answers arrive as HTML artifacts, and every UI has a diff viewer.
  • Remote, without the setupNo port forwarding, no VPN. Each tamale connects out to the hub; only your browser holds the key.

Install

macOS and Linux:

curl --proto '=https' --tlsv1.2 -LsSf https://github.com/bigmah/tamale/releases/latest/download/install.sh | sh

Or build from source with Rust:

cargo install --git https://github.com/bigmah/tamale --locked

Then run tamale. Run tamale update later to get the latest release.

Use it from anywhere

  1. Make a key below. It's made in your browser; the hub never sees it.
  2. On each machine, set TAMALE_HUB_KEY where tamale runs and run /remote in tamale.
  3. On your phone, scan the key's code. Your sessions show up here; tap one to drive it.

Want your own hub? See the self-hosting guide, or browse the docs.

          How much to trust this hub
          
    Sessions are end-to-end encrypted between tamale and your browser. Your key is made in this
            browser and never reaches this server. Whoever runs the hub, or breaks into it, can't read your
            prompts, code, tool output, artifacts, titles or directories, and can't send commands to your
            machines.
    
          
    Three limits. This server delivers the page code, so someone in control of
            it could change that code to steal a key the next time a page loads, or as one is made;
            encryption makes an attack take that active step, but doesn't rule it out. It still sees
            metadata: which sessions exist and when, from which addresses, whether they're
            busy, and message sizes and timing. And it can't protect a compromised laptop or phone: a
            machine that holds a key can reach every other machine using it, and in tamale's
            auto mode run commands there without approval. Give machines you trust less a key
            of their own. It's a beta: for anything sensitive, run your own hub (it's one small binary
            behind Caddy), and keep tamale's permission mode on ask for remote work.
    
          
    Unused keys made here are deleted after 7 days if they never connect, and after 90 days
            without use.
